# Spaced Repetition (Medical SRS) — AI Context File
_Last synced: 2026-06-10 @ 55ab32e_

## 1. What This Is (Plain English)
- **In one sentence:** A study planner that holds the **entire FMPM medical-school curriculum (S1→S10, ~1310 lessons)** and tells you which lessons to review today — and, run online, drops those reviews onto your Google Calendar.
- **Why it exists:** You can't track ~1310 lessons by hand. You log *when* you studied a topic and *how well you recalled it* (0–5); the system computes when to review it next and **recovers gracefully** when you miss days instead of dumping everything into one panic pile.
- **Who uses it:** Just the owner — a medical student (curriculum is French-language FMPM, in `data/`). Personal tool: low blast radius, but their real study schedule rides on it, and the sheet holds real study progress (see §6).
- **Vibe:** Polished personal tool, heavily iterated (see the `spaced repetition old/` graveyard). It's really **three things that work together**: a spreadsheet, a companion Apps Script, and a Python script that regenerates the spreadsheet from the curriculum.

## 2. How To Run It
No build, no install, no npm. Two ways to *use* it, one way to *rebuild* it.

### Online (full features — Google Sheets + Calendar sync)
1. Upload **`srs-system.xlsx`** to Google Drive, open as a Google Sheet.
2. **Extensions → Apps Script**, paste all of **`srs-appscript.js`**, save.
3. Run `setupTriggers()` once, grant permissions. A **📚 SRS** menu appears; reviews auto-sync to Google Calendar.

### Offline (tracker only — Microsoft Excel)
- Open **`srs-system.xlsx`** directly in Excel. Every formula, the Dashboard, Module View and Weekly tabs recalc. **No calendar sync** (Apps Script is Google-only) and the Module View lesson list needs Excel 365 (see §6).

### Daily use (both)
Type in **two columns only** on `lesson-database`: **F = Last Review** (Ctrl+; = today) and **G = Mastery 0–5**. Everything else fills itself in. Filter with the **▼ arrows on row 2** (Semester / Module / Subject), or use the **Module View** tab.

### Rebuild / extend the workbook
```
python3 scripts/build_srs_xlsx.py     # run from repo root (needs: pip install openpyxl)
```
Edit `data/curriculum_FMPM_S1-S10.txt`, re-run, and the workbook is regenerated. It **preserves your study progress** by re-matching `Semester | Module | Lesson` (see the caveat in §6).

- **Required env vars:** None. Auth is Google-account consent at Apps Script setup time. No keys in the repo.

## 3. Tech Stack
- **Spreadsheet** — `srs-system.xlsx`, generated by openpyxl. 5 sheets, charts, data bars, AutoFilter, dropdowns. Logic is plain cell formulas (`IF`, `TODAY`, `COUNTIF(S)`, `COUNTA`, `INDEX/MATCH`, `FILTER`) — chosen to work in **both** Excel and Google Sheets.
- **Google Apps Script (V8 JS)** — `srs-appscript.js`. Single file, global functions, no deps. Uses `SpreadsheetApp`, `CalendarApp`, `ScriptApp`, `Utilities`.
- **Python 3 + openpyxl** — `scripts/build_srs_xlsx.py`, the workbook generator. The only place with a real dependency (`openpyxl`).
- **What kind of project:** a spreadsheet + companion script + generator, version-controlled. No package manager, no CI, no LICENSE (all absent).
- **External services:** Google Sheets, Google Calendar (the account's *default* calendar). Online mode only.

## 4. Code Map (The Important Files Only)
- `srs-appscript.js` — **the online engine.** `syncToCalendar` (the loop), `smartReschedule`, `showDailyDigest`, triggers (`setupTriggers`/`onEditTrigger`), menu (`onOpen`). Its top comment is the authoritative column map.
- `srs-system.xlsx` — **the data + offline brain.** 5 sheets:
  - **`lesson-database`** — the engine; ~1310 lessons, rows 3–1312; AutoFilter on row 2. Header is 2 rows.
  - **`Dashboard`** — **macro / bird's-eye**: KPIs, per-semester & per-module tables with % data bars, and 4 charts.
  - **`Module View`** — **micro**: one dropdown picks a module → stat panel + mastery chart + filtered lesson list.
  - **`Weekly`** — next-7-days workload + chart.  **`How-To`** — one-screen guide.
- `scripts/build_srs_xlsx.py` — regenerates `srs-system.xlsx` from `data/`, preserving progress. **Edit structure/visuals here, not by hand in the binary.**
- `data/` — the curriculum. `curriculum_FMPM_S1-S10.txt` is the **single source of truth** (the per-semester `sX liste cours.txt` files are byte-identical slices of it).
- `backups/simple system/` — **READ-ONLY.** Older, simpler variant with a *different* column layout (see §6).
- `spaced repetition old/`, `ai-report.txt` — history/design notes. `ai-report.txt` predates the rebuild (mentions ~90 lessons & `medical_srs_v2.xlsx`).

### Column map — `lesson-database`, data from row 3 (MUST match `srs-appscript.js` `CONFIG.COL`)
`A` # · `B` Semester · `C` Module · `D` Subject · `E` Lesson · `F` **Last Review (you type)** · `G` **Mastery 0–5 (you type)** · `H` Interval · `I` Next Review · `J` Status · `K` Priority · `L` Synced (script) · `M` Event ID (script, hidden).

### The core SRS rule (lives in TWO places — keep them identical)
Mastery → days to next review: **0→1, 1→3, 2→7, 3→14, 4→30, 5→done**.
- Sheet (col H): `IF(G=0,1,IF(G=1,3,IF(G=2,7,IF(G=3,14,IF(G=4,30,60)))))`
- Script: the array `[1, 3, 7, 14, 30, 60]` (`srs-appscript.js`, in `smartReschedule`).
- Next Review `I = F + H`. Mastery **5 = DONE** → dropped from the calendar.
- Calendar title format: `📚 s3 - Sémiologie I | Diarrhée aiguë` (`buildTitle_`).

### Legends
- **Status (J):** `⚪ NEW` · `✅ DONE` · `🔴 OVERDUE` · `🟢 TODAY` · `🔵 TOMORROW` · `📅 THIS WEEK` · `⏳ SCHEDULED`.
- **Priority (K):** days until due (negative = overdue). `999` = new/no date, `9999` = mastered.

## 5. Rules For Editing This Code
- **Change the interval rule in BOTH files or neither.** Sheet col-H formula and the `[1,3,7,14,30,60]` array in the script must agree, or online vs offline drift. #1 rule.
- **Columns A–M positions are load-bearing.** The Apps Script reads cells by index. If you reorder columns in the generator, update `CONFIG.COL` in `srs-appscript.js` (and `onEditTrigger`, which watches F & G).
- **Edit structure via the generator, not the binary.** Add lessons / change layout in `data/` + `scripts/build_srs_xlsx.py`, then re-run. Editing the `.xlsx` by hand is fine for content but won't survive a regenerate.
- **Keep sheet formulas cross-compatible** (offline depends on it): only functions in *both* Excel and Sheets. `FILTER` is the one exception — it degrades gracefully (see §6).
- **You only edit columns F and G.** Don't add manual-input columns that collide with G–M.
- **`backups/` is read-only — never modify anything inside it.** (Owner rule.)
- Apps Script style: one file, global functions, no `require`/npm. Trailing-`_` functions are private helpers. `HEADER_ROWS = 2`; data starts row 3.

## 6. Fragile Bits & Landmines
- **There IS real study progress in the sheet** (~7 lessons reviewed in S8, Feb–Mar 2026). Never blow it away. The generator preserves it by matching `Semester|Module|Lesson` — **but if you rename a module or lesson in `data/` and then regenerate, that lesson's key no longer matches and its progress is dropped.** Rename carefully; the old `.xlsx` is recoverable via git.
- **Module View's lesson list uses `FILTER`** — works in Google Sheets and Excel 365, but on older Excel it shows a fallback message. The universal way to browse a module is the **AutoFilter on `lesson-database`**. Stats/charts everywhere else use `COUNTIF(S)` and work in all versions.
- **Formula ranges are bounded to `$3:$2000`** (≈690 rows of headroom over the ~1310 lessons). If the curriculum ever exceeds ~2000 lessons, bump `LAST` in the generator and regenerate — otherwise new rows won't be counted.
- **The `smartReschedule` "fake Last Review" trick:** it back-dates `Last Review = target − interval` so `I = F + H` lands on the target day, re-deriving interval from the same `[1,3,7,14,30,60]` array. Changing that array breaks rescheduling silently.
- **`onEditTrigger` has a deliberate `Utilities.sleep(1500)`** so formulas (I/J) recalc before sync reads them; it only fires on edits to F and G. Don't remove the sleep.
- **`parseDate_` rejects years <2025 or >2100** as junk-data guard; a date outside that range is treated as "no date" (deletes its event). Bump the bound before it matters.
- **The simple backup has a totally different column layout** (`A=Subject…H=Synced`, no Semester/Module/Priority/Event-ID). Never copy its `CONFIG` into the current script.
- **Dashboard/Module View tables live at fixed rows** (per-semester 14–23, per-module 46–89, charts anchored to them). Don't hand-insert rows on Dashboard — regenerate instead.
- **LibreOffice headless can't open xlsx in this container** (env limitation, not the file). To verify formulas, use the pure-Python `formulas` lib on small samples — note it mis-evaluates the `"<>"` non-blank criterion, which is correct in real Excel/Sheets.
